# 新手入门说明书（成员版 · Java / Spring Boot）

> 给 A~E 五位成员。你**不需要会写代码**：写代码的活让 DSH 里的 AI 干，你负责说清楚、检查对错、把报错丢回去让它改。
> 本项目 = 5 个"数字员工"按顺序各干一段招聘活。你只负责你自己的**那一个 Java 类**。

## 0. 你的活一句话

> 你的类 `run()` 干的事：**吃进一个 JSON，返回一个 JSON，中间调一次 AI（DeepSeek）。**
> 做完交给"整合者"把 5 个串起来；后端（Spring Boot 网页）是最后的事，现在不用管。

## 1. 你只碰自己的那个文件

| 成员 | 数字员工 | 只准改这个文件 |
|---|---|---|
| A | 招聘分析师 | `src/main/java/com/hragent/agent/analyst/AnalystAgent.java` |
| B | 简历猎手 | `src/main/java/com/hragent/agent/scout/ScoutAgent.java` |
| C | 面试官 | `src/main/java/com/hragent/agent/interviewer/InterviewerAgent.java` |
| D | 测评背调员 | `src/main/java/com/hragent/agent/assessor/AssessorAgent.java` |
| E | offer 管家 | `src/main/java/com/hragent/agent/concierge/ConciergeAgent.java` |

其余（`Agent.java`、`DeepSeekClient.java`、`pom.xml`、别人的类、`dispatcher/`、根目录文件）一律**只读、不许改**。规则细节见 `SKILL-上传规则.md`。

## 2. 每次开工的步骤

1. 用 **IDEA** 打开 `hr-agent-team`（自动按 pom 拉依赖）；确认 IDEA 里配好了 `DEEPSEEK_API_KEY`（Run/Debug 配置的环境变量）；
2. 打开你自己的类文件（见上表）；
3. 在 DSH（或 IDEA 里的 AI 助手）里，让 AI 帮你把文件里的 `ROLE` 和 `run()` 写好；
4. 自测：右键运行你这个类自带的 `main`，看能不能打印出 JSON；
5. 通过后，交给整合者。

## 3. 对 AI 说的话术（照抄，改名字/路径）

> 我在主仓库 `hr-agent-team` 里，是【成员 A/B/C/D/E】，只准修改文件【你自己的那个 .java 路径】。
> 请把文件里的 ROLE 写成【数字员工名】的提示词：说清职责；写明输出字段（照 `SKILLS技能注册表.md`）；该有的枚举只准取这些值；风格"结论→依据→风险→下一步"；禁止编造。
> run() 里用 `com.hragent.common.DeepSeekClient` 的 `callJson` 调模型，返回前校验字段。不要改类名、方法名 run 或签名。只改这一个文件，其它只读。
> 另：ROLE 里要写明本 agent 会用哪些工具（如 `doc_writer`），run() 里必须**真调用至少一个工具**把成果落成文件，不只生成文字（见《工具调用规范》）。

## 4. 四条铁律

1. 调模型只用 `common/DeepSeekClient`，不自己另写；
2. 只做"吃进 JSON → 吐出 JSON"，字段照契约不自创；
3. 只改自己那一个 .java，别的只读，绝不越界；绝不提交含 key 的文件；
4. **必须真调用至少一个工具**把成果落成文件（.csv/.html），**不能只生成文字**就交差（详见《工具调用规范》）。

## 5. 出错三板斧

1. 报错 → 整段贴给 AI 让它改；
2. 输出字段不对 → 让它"严格按契约改，别自创字段"；
3. 还不行 → 找整合者或老师。

## 6. 交付（做完交整合者这 4 样）

1. 你改好的 .java；2. 你的 ROLE 全文；3. 1 组输入样例+期望输出；4. 一句输出字段说明。

> 就这么多。第 2 步开始照做，卡住回来翻第 3 节的话术。
