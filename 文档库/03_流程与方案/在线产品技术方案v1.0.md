# 在线产品技术方案 v2.0（Java / Spring Boot）

> 目标：把 HR 多智能体系统做成一个**部署上线、网页即可用**的在线产品。使用者只访问网页，接触不到开发框架。
> 技术栈（v2.0 定稿）：**后端 Spring Boot（Java）**，agent 也是 Java；前端 HTML/JS/CSS；与 v1.0（FastAPI/Python）不同，本版为最终方案。
> 当前阶段：5 个 agent 各自开发中；后端与前端是**整合完成之后**的事（本文件是"到时候怎么做"的蓝图，先行定稿以免后端再摇摆）。

---

## 0. 一句话定位

> 用户打开网页 → 输入一句招聘诉求 → 后端 Spring Boot 里的 5 个数字员工在线协同，按序调用 DeepSeek → 端到端产出报告/表格/网页成果 → 用户在网页查看与下载。

---

## 1. 架构（部署拓扑）

```
浏览器（前端 HTML/JS/CSS）
   │  HTTP/JSON
   ▼
Nginx（反向代理 / 静态托管 / 可选域名+证书）
   │
   ▼
Spring Boot 应用（Java 17，Maven，打成可执行 jar）
   ├─ Controller 层       接收请求、返回进度、提供下载
   ├─ 调度层 Dispatcher    按 A→B→C→D→E 顺序调用 5 个 agent，传 JSON
   ├─ 5 个 agent           各自实现 Agent 接口的 Java 类
   ├─ DeepSeekClient      统一调用 DeepSeek（common 层）
   └─ 数据层              任务/候选人档案落库（MySQL 或 H2）
```

**长任务关键设计**：一轮招聘 A→E 要跑几十秒到几分钟，前端不能傻等。
→ 采用「异步任务 + 轮询/SSE」：`POST /recruit` 立即返回 `jobId`；前端每秒查进度（谁在干活、到哪步），跑完展示成果。进度日志 = 可追溯 + 数字员工协同的演示素材。

---

## 2. 技术选型

| 组件 | 选型 | 说明 |
|---|---|---|
| 后端 | **Java + Spring Boot**（Maven，Java 17）| 与现有 agent（Java）同一套，不返工 |
| Web 层 | Spring Web + Controller | 提供 REST / 静态页 |
| agent | 5 个 Java 类实现 `Agent` 接口 + 调度层 | 已有骨架 |
| 调模型 | `common/DeepSeekClient` | key 只放服务器端环境变量 |
| 数据库 | MySQL（生产）/ H2（本地开发）| 存任务、候选人档案、成果；也可先用文件 |
| 异步 | `@Async` 或 TaskExecutor + 轮询/SSE | 长任务不阻塞 |
| 前端 | 单页 HTML/JS/CSS | 只做展示，逻辑全在后端 |
| 部署 | 云服务器 + `java -jar` + Nginx | 可选域名/HTTPS |

---

## 3. 5 个 agent 如何接进 Spring Boot

- 每个 agent 已经是 Java 类，只需：实现统一 `Agent` 接口（已有），加 `@Service`（或放进一个 Map/List 由调度器持有）；
- 调度层 `RecruitmentDispatcher`：`analyst.run(...) → scout.run(...) → ... → concierge.run(...)`，每一步结果 `ObjectMapper` 读写共享状态、落库；
- offer 前留**人工确认节点**：后端返回"待确认"，用户在网页点确认后再继续。

---

## 4. 前后端接口约定（简）

```
POST /api/recruit                body: { demand, resumes? }
GET  /api/recruit/{jobId}         → { status, stage, logs[], verdict?, artifacts? }
POST /api/recruit/{jobId}/confirm   （offer 人工确认：accept/reject）
GET  /files/{id}                 下载/打开某份成果（报告/表格/网页）
POST /api/chat                   （可选）页面里随口问一句
```

前端页面板块：①输入诉求 ②实时进度流（谁在干活）③人工确认按钮 ④成果列表（打开/下载）。

## 5. 部署（真·在线，最后阶段做）

1. 云服务器（阿里/腾讯轻量，Ubuntu，内存 ≥2G）；
2. `mvn clean package` 打成 jar；`DEEPSEEK_API_KEY` 写进服务器环境变量（不写进前端/不进 git）；
3. 用 systemd / nohup 常驻运行 `java -jar`；
4. Nginx 反代到本地端口 + 托管前端静态页；要公网域名+HTTPS 再配；
5. 防火墙放行、数据库落盘持久化。

---

## 6. MVP-first 里程碑（真写后端时按此推进）

| 里程碑 | 内容 | 出口标准 |
|---|---|---|
| M1 骨架 | Controller + 异步任务 + 单页前端 + POST/GET | 网页能发起任务、看到进度 |
| M2 最小闭环 | 只串 A→B，产出一份打分成果 | 网页能下载 1 份成果 |
| M3 全链路 | 串 A→E + 人工确认 + 成果列表 | 端到端产出 3 类以上成果 |
| M4 打磨+上线 | SSE 进度、样式、部署、录屏 | 公网可访问 |

---

## 7. 风险与兜底

| 风险 | 兜底 |
|---|---|
| 部署踩坑（服务器/Nginx） | 先用 IP:端口上线；报错丢给 AI 修；实在不行录屏兜底 |
| API 成本 | 限量开放/只给评委用 |
| 长任务中断 | 进度持久化 + 分步可重试 + 断点续跑 |
| 排错 | 报错整段丢回 AI |
