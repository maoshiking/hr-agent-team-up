## 2. 待补点 ①：真·工具调用（最优先）

让 agent 不再只"生成文字"，而是**调用函数去执行**，演示时能看到"Agent 正在调用 xx 工具"。

### 招聘场景最易做的三个真工具
1. **简历解析器 `resume_parser`**：把简历文本/PDF 提取成结构化字段；
2. **文档/文件生成器 `doc_writer`**：把结果落成 `.csv` / `.html`（成果本就是文件，这就是"真行动"）；
3. **薪资/公司检索**（可选加分）：查岗位行情、查公司背景。

### 整合者阶段小任务清单
- [ ] 给 `DeepSeekClient` 加一层 **function-calling / tool** 支持（模型决定调哪个，后端执行，结果回给模型）；
- [ ] 写 `resume_parser` 工具：简历 → 结构化 JSON；
- [ ] 写 `doc_writer` 工具：把 agent 的 JSON 写成本地 .csv / .html；
- [ ] 让 B(简历猎手) 用 `resume_parser`、各 agent 用 `doc_writer` 产出文件；
- [ ] 演示页面显示"正在调用 xx 工具"。

> 目标：让评委看到 agent **真的在干活、在产出文件**，而不是只会聊天。

## 3. 待补点 ②：看得见的自主规划（低成本）

把"固定流水线"讲成/做成"自主规划"：
- 调度器输出**决策理由**："本轮判断需要做 X、Y、Z 三步，因为…"；
- 加几个**分支决策**：
  - 候选人不足 → 先扩大检索/提醒扩源；
  - 初筛全不通过 → 停下并说明原因，不回填 offer；
  - offer 被拒 → 回到名单下一个候选人。

### 落地
- 整合者在 dispatcher 里加少量 `if/else` 分支 + 把"当前判断/下一步"作为日志输出；
- 演示时让 A 先给"计划"，再逐步执行 → 观感从"流水线"变成"会规划的数字员工"。
