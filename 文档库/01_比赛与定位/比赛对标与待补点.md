# 比赛对标与待补点

> 用赛题逐条检验作品，明确"已达标 / 有差距 / 待补"，并给出待补点怎么做。供全队对齐 + 答辩前核对。

---

## 1. 对标总表

| 赛题强调 | 我们的对应 | 现状 |
|---|---|---|
| 交付报告 / 表格 / 网页等可验收成果 | 成果工作台（报告 A/C/D、表格 全部、网页 A/C/E）| ✅ 扎实，最大亮点 |
| 多智能体协同 | 5 个数字员工 A→E | ✅ 强项、贴题 |
| 接管一段端到端流程 | 模糊诉求 → offer/入职 完整闭环 | ✅ 完整 |
| 真实工作/行业场景 | 招聘 = 办公/人力资源 | ✅ 真实、有付费方 |
| 理解复杂/模糊意图 | A 招聘分析师"需求澄清追问" | ✅ 演示时要突出"模糊→澄清" |
| **工具调用与环境交互** | agent 基本只做"prompt→模型"，少真调用外部工具 | ⚠️ 硬伤，最该补 |
| **自主规划任务** | 固定 A→B→C→D→E 顺序 | ⚠️ 偏弱，像流水线非"自主决策" |
| RAG / 检索增强 | 未接知识检索 | ❌ 加分项，可后置 |
| 长短期记忆 | 仅概念，无实现 | ❌ 加分项，可后置 |
| 多模态交互 | 纯文字 | ❌ 加分项，可后置 |

**结论**：结构与可验收成果完全符合赛题；卡分点在"工具调用"与"自主规划"（正是赛题用来区分问答机器人的两点）。

---

## 2. 待补点 ①：真·工具调用（最优先）

让 agent 不再只"生成文字"，而是**调用函数去执行**，演示时能看到"Agent 正在调用 xx 工具"。

### 招聘场景最易做的三个真工具
1. **简历解析器 `resume_parser`**：把简历文本/PDF 提取成结构化字段；
2. **文档/文件生成器 `doc_writer`**：把结果落成 `.csv` / `.html`（成果本就是文件，这就是"真行动"）；
3. **薪资/公司检索**（可选加分）：查岗位行情、查公司背景。

### 整合者阶段小任务清单
- [ ] 给 `DeepSeekClient` 加一层 **function-calling / tool** 支持（模型决定调哪个，后端执行，结果回给模型）；
- [ ] 写 `resume_parser` 工具：简历 → 结构化 JSON；
- [ ] 写 `doc_writer` 工具：把 agent 的 JSON 写成本地 .csv / .html；
- [ ] 让 B(简历猎手) 用 `resume_parser`、各 agent 用 `doc_writer` 产出文件；
- [ ] 演示页面显示"正在调用 xx 工具"。

> 目标：让评委看到 agent **真的在干活、在产出文件**，而不是只会聊天。

---

## 3. 待补点 ②：看得见的自主规划（低成本）

把"固定流水线"讲成/做成"自主规划"：
- 调度器输出**决策理由**："本轮判断需要做 X、Y、Z 三步，因为…"；
- 加几个**分支决策**：
  - 候选人不足 → 先扩大检索/提醒扩源；
  - 初筛全不通过 → 停下并说明原因，不回填 offer；
  - offer 被拒 → 回到名单下一个候选人。

### 落地
- 整合者在 dispatcher 里加少量 `if/else` 分支 + 把"当前判断/下一步"作为日志输出；
- 演示时让 A 先给"计划"，再逐步执行 → 观感从"流水线"变成"会规划的数字员工"。

## 4. 可后置（时间紧先跳过，答辩当扩展方向提）

RAG/检索、长期记忆、多模态 —— 赛题是"鼓励"而非"必须"，做不好反拖技术可行性分。有余力再补，并作为答辩"未来方向"讲即可。

## 5. 一句话

> 我们的**闭环 + 可验收成果已稳**；答辩拿高分的**最省力动作 = 补"真工具调用" + 让"自主规划"看得见**。先保这两点，再谈加分项。
