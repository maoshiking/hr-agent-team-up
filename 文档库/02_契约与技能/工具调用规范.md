# 工具调用规范（所有 agent 必读）

> 背景：比赛强调 agent"调用工具与环境交互"是区别于"问答机器人"的关键。因此**所有 agent 不允许只"生成文字"交差**，必须至少有一次**真实的工具调用/行动**。
> 本规范对 A~E 全部数字员工生效，是硬性规定。

## 1. 强制要求（对每个 agent）

1. 每个 agent 必须在 `run()` 里**真调用至少 1 个共享工具**（不是只把输入丢给模型生成文字）；
2. 产出成果必须**落成真实文件**（用 `doc_writer` 写 `.csv` / `.html` / `.md`），因为"成果是文件"才是可验收 + 真行动；
3. 禁止把"一段纯文本回复"当作交付物；
4. 工具由共享层/整合者实现一次；成员只负责在自己的 agent 里**声明"用哪些工具、什么条件下调"**（写进 ROLE）。

## 2. 共享工具集（成员可声明使用）

| 工具 | 作用 | 典型使用者 |
|---|---|---|
| `resume_parser` | 简历文本/PDF → 结构化字段 | B 简历猎手 |
| `doc_writer` | 把结果写成 `.csv` / `.html` / `.md` 文件（= 真成果）| 全部 agent |
| `search_web`（可选加分）| 联网检索（如薪资行情、公司背景）| 视需要 |

> 工具的"实现 + function-calling 循环"由共享 `DeepSeekClient` / 整合者接好一次；成员不写工具实现，只负责在 ROLE 里写清楚"何时调谁、怎么用结果"。

## 3. 成员怎么落地（照抄进 ROLE / run()）

在你自己的 agent 里：
1. `ROLE` 里写明："本 agent 会用到的工具：`doc_writer`（把结果写成文件）…；当需要把结果落成文件时调用 `doc_writer`"；
2. `run()` 里：模型返回结果后，**调用对应工具**把结果写成文件（先本地生成一份示例文件自测）。

## 4. 每个 agent 建议的工具用点

| agent | 建议工具调用 |
|---|---|
| A 招聘分析师 | `doc_writer`：把 JD / 画像写成本地文件 |
| B 简历猎手 | `resume_parser`：解析简历；`doc_writer`：写打分表 .csv |
| C 面试官 | `doc_writer`：写题纲/纪要 .html、评分 .csv |
| D 测评背调员 | `doc_writer`：写测评报告 .html、风险清单 .csv |
| E offer 管家 | `doc_writer`：写 offer .html、入职计划网页 .html |

## 5. 验收一句话

> 演示/交付时，要能看到"Agent 正在调用 resume_parser / doc_writer"——**它真的在行动、在产出文件**，而不是只会聊天。
